The Labeler and the Installer

This week Amazon showed that AI agents found a zero-day in a medical labeling tool in about 11 minutes. Then CISA added a Drupal installer flaw that was already being used on live sites a day after the patch.

On November 20, Amazon Threat Intelligence published its findings. Investigators had found a publicly hosted instance of Cairn, an open-source autonomous penetration-testing framework, running with no authentication. The operational history was visible to anyone on the internet: project configurations, prompts and the agents' output. The prompts were in Simplified Chinese. The timestamps were set to China Standard Time. (VERIFIED, Amazon)

The campaign ran for about 48 hours, beginning September 8, 2026, against IP addresses tied to universities in East Asia outside mainland China. The operator gave the agents a list of addresses and variations of one goal: "obtain shell access." Amazon says the agents then "planned, executed, and adjusted their approach as they learned, without the operator choosing each next step." (VERIFIED, Amazon)

Not every run worked. Against an open Redis server, the agents spent roughly 16 hours and 148 sequential actions and still failed. Against a university GPU server, they spent more than six hours, built a list of about 80 real usernames from public faculty pages and papers, and tested more than 30,000 credential combinations. That failed too. (VERIFIED, Amazon)

Then the line that matters.

Against a target running an open-source medical imaging AI application, Amazon writes, the agents mapped the application's API, found an upload endpoint with a filename parameter, and tested it for path traversal. "In about 11 minutes, the agents went from mapping the application's API to arbitrarily writing files on the server." In a later session they used the same flaw to get a reverse shell running as root. Amazon assesses with high confidence that this was a zero-day. At the time, there was no fix, no advisory, and no mention in vulnerability databases. (VERIFIED, Amazon)

Amazon did not name the product in the blog. The CVE record for CVE-2026-133968 does the linking: MONAI Label, before 0.8.6, "as exploited in the wild starting in September 2026." MONAI Label is an open-source tool for labeling medical images for AI training. The project's advisory says the original report came from AWS. (VERIFIED, CVE.org and MONAI Label)

On November 22, the project shipped 0.8.6 and called it a security release. Authentication is disabled by default, the notes say, so both of the flaws in that release "were reachable by any client that can connect to the server." The CVE record scores it 9.8. (VERIFIED, MONAI Label 0.8.6 and CVE.org)

After the agents found the zero-day, the human operator stepped back in and gave them a proxy into a second university network running the same software. Amazon infers the actor had already used the flaw to get that tunnel, then pointed the agents at other machines inside. Amazon assesses with moderate confidence that this is a Chinese-nexus actor, based on the language of the prompts, the time zone and the choice of targets. (VERIFIED as Amazon's account and assessment)

CISA added CVE-2026-133968 to its Known Exploited Vulnerabilities catalog on November 23, "based on evidence of active exploitation." The federal due date is November 26, 2026. That's Thanksgiving Day. (VERIFIED, CISA)

Now leave the lab and go to the installer.

On November 18, Drupal shipped a highly critical fix for CVE-2026-132165, found by Anthropic's OSS Scanner. Drupal core ships with install.php, the script that sets up a new site. "Under specific conditions, an attacker can use the installer to attempt to reinstall Drupal. This can lead to a site takeover or remote code execution." Drupal rates it 20 out of 25, the top tier on its own risk scale. (VERIFIED, Drupal SA-CORE-2026-017)

The patches landed in 10.6.22, 11.3.22 and 11.4.13. Older branches, including Drupal 8 and 9, are end-of-life and do not get a fix. (VERIFIED, Drupal) A later update to the same advisory said the Security Team "has received a report this was exploited on live sites as early as 2026-11-19 19:00 UTC." That's about a day after the fix. (VERIFIED, Drupal)

On November 24, CISA added the Drupal flaw to the KEV catalog, again "based on evidence of active exploitation." The federal due date is November 27, the Friday after Thanksgiving. (VERIFIED, CISA) CISA's alert says this class of flaw "poses significant risks to the federal enterprise." CISA also encourages all organizations to give priority to flaws in the KEV catalog. (VERIFIED, CISA)

Drupal's own advice is plain. Upgrade. And "securing the Drupal installer after installation." If you can't patch yet, block access to /core/install.php and make sure the web server cannot write to settings.php. Some, but not all, attack paths are blocked when settings.php is locked down. (VERIFIED, Drupal)

Here's my read (thesis, not fact): this is one story about doors nobody is watching.

A labeling server in a lab, auth off, sitting on a network because someone needed to tag scans. An installer script that has to exist once, and then stays on the site. Amazon's agents found the first one in about 11 minutes, as a zero-day. An AI scanner found the second for the defenders. Live sites were hit about a day after the patch.

I'm e/acc on this. The same class of agent that found the lab door can find yours, and it can also help you close it. The gap is not the tools. It's whether the forgotten box gets a human in time. CISA's clock on the labeling tool runs out on Thanksgiving. The Drupal clock runs out the next day. Holiday week is when this hurts.

Sovereign move for the next 24 hours: two things. First, check whether you run MONAI Label. If you do, upgrade to 0.8.6. Turn authentication on. Take it off the public internet. If an older server was reachable from an untrusted network, the project says to review it for unexpected file changes before you put it back in service.

Second, check whether you run Drupal 10 or 11, including the old marketing site someone stood up years ago. Upgrade to 10.6.22, 11.3.22 or 11.4.13. If you can't do that today, block /core/install.php at the web server and make settings.php read-only. Then look at whether someone already used the door. Drupal 10.5 and below, and 11.2 and below, are end-of-life. Those need a supported branch, not a promise to get to it after the holiday.
